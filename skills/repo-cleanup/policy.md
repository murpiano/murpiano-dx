# Следы агентной разработки

Что считается следом и где его быть не должно. Не применяется к репозиториям, которые сами
являются инструментами для агентов (например, `murpiano-dx`).

## 1. Где проверять

Всё, что видит посетитель репозитория:

- отслеживаемые файлы и их содержимое;
- каждый коммит в опубликованных ветках и тегах: сообщение, трейлеры, автор, коммиттер;
- названия веток и тегов;
- pull request: название, описание, ветка;
- релизы: название и заметки;
- description и topics репозитория.

## 2. Файлы

Не отслеживаются и не встречаются в опубликованной истории. Список: [gitignore-agents](../../global/gitignore-agents).

## 3. Текст

Нигде в зоне проверки нет упоминаний ассистентов, агентов, моделей и генерации: названий
ассистентов и вендоров, `Generated with`, `Generated by`, `AI-generated`, `as an AI`,
`Co-Authored-By` с ассистентом или ботом, эмодзи робота.

Исключение: упоминание, которое часть самого продукта (например, интеграция с API модели).
Такое подтверждает автор.

## 4. Автор

Все авторы и коммиттеры в опубликованной истории — владелец с одним email: noreply-адресом
его аккаунта. Для репозиториев murpiano:
`Bogdan Trotsenko <159007823+murpiano@users.noreply.github.com>`.

- Имя — как в профиле GitHub. В старых коммитах может стоять `murpiano`: email тот же,
  GitHub показывает их как коммиты владельца, переписывать не нужно.
- Коммиттер `GitHub <noreply@github.com>` у коммитов, сделанных на сайте (merge по кнопке),
  нормален.
- Настоящий email в истории — находка: GitHub подставляет его при merge на сайте, если в
  аккаунте не включено «Keep my email addresses private» (Settings → Emails). Оба
  переключателя, и этот, и «Block command line pushes that expose my email», включены с
  2026-10-17.
- Коммиты до 2026-10-17 с настоящим email или другим именем оставлены как есть: так решил
  владелец. Сканер покажет их как находку; принять её, историю ради автора не переписывать
  и не предлагать. Стандарт действует для новых коммитов.

## 5. Сообщения и ветки

- Сообщения коммитов, названия PR и релизов без эмодзи и по конвенции репозитория. Если в
  репозитории нет своей, используется пресет kysaro по умолчанию:
  [правила](https://github.com/murpiano/kysaro#message-format).
- Ветки не начинаются с `claude/`, `copilot/`, `codex/`, `cursor/`, `devin/`, `ai/`,
  `agent/`.

## 6. Профилактика

`sync.py` подключённых проектов настраивает их так, что следы не появляются:

- список из `global/gitignore-agents` прописан в `.git/info/exclude` каждого
  подключённого проекта (`exclude_agent_files`);
- этот pre-commit-хук установлен в каждом подключённом проекте
  (`install_precommit_hook`), пока в нём нет своего несвязанного хука; он видит
  только staged-файлы и diff, не текст самого сообщения коммита;
- commit-msg оборачивается тем же сканером отдельно (`install_commitmsg_hook`,
  [commit-msg-hook.sh](commit-msg-hook.sh)) — только если хук там уже есть (свой
  у [Kysaro](https://github.com/murpiano/kysaro) или кастомный), с нуля не ставится, чтобы не спорить за
  файл с установкой Kysaro; оригинальный хук запускается первым, затем проверяется
  текст сообщения на упоминания из раздела 3;
- автор git в новом проекте без истории — владелец из раздела 4 (`sync.py`
  при `init`); проверить `attribution` в настройках агента отдельно.

## 7. Что нельзя убрать

GitHub хранит `refs/pull/<n>/head` каждого PR с исходными коммитами. Удалить их может только
поддержка GitHub. Форки и чужие клоны тоже сохраняют старую историю.

## 8. Секреты

Сканер заодно ищет секреты: файлы `.env` (кроме `.env.example`, `.env.sample`,
`.env.template`), ключи `*.pem`, `*.key`, `id_rsa`, `.npmrc`, `credentials.json`, приватные
ключи в тексте, токены GitHub, OpenAI, Anthropic, AWS, Slack, Google и присваивания вида
`token = <длинное значение>`. В отчёте только путь, строка или коммит, само значение не
выводится.

- Секрет в рабочем дереве: убрать из файла, перенести в переменную окружения, файл добавить
  в `.gitignore`.
- Секрет в истории уже утёк, если был push. Сначала отозвать и выпустить новый у
  сервиса, затем по желанию автора вычистить историю (`--index-filter` или
  `git filter-repo --replace-text`). Вычистка без отзыва не помогает.
- Тестовые и примерные значения, которые сканер принял за секрет, автор помечает как
  ложное срабатывание.
