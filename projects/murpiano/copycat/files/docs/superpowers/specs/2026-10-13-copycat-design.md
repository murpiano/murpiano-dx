# Copycat — менеджер истории буфера обмена (Windows desktop)

## Цель

Десктопное приложение для Windows: история всего скопированного (текст,
изображения, файлы), с быстрым доступом по категориям, поиском по
названию/содержимому и тегами. Визуальный референс: `raw/template.png`
(тёмная тема, поиск сверху, вкладки History/Starred, ряд тег-фильтров,
горизонтальная лента карточек).

Успех: пользователь жмёт глобальный хоткей из любого приложения, видит
последние скопированные элементы, находит нужный поиском или тегом,
вставляет его одним действием.

## Стек

- Electron (main process) + React + TypeScript (renderer).
- SQLite через `better-sqlite3` для хранения метаданных и истории.
- `react-window` для виртуализации ленты карточек.
- Состояние в renderer — Zustand.

## Архитектура

### Main process

- **Clipboard watcher**: поллинг `electron.clipboard` (~500мс) +
  обработка `CF_HDROP` для файлов из проводника. Дедупликация по хэшу
  содержимого (text/image) или по списку путей (file), чтобы повторное
  копирование того же не плодило дубли подряд.
- **Storage**: SQLite в `%APPDATA%/Copycat/db.sqlite`.
  - `items(id, type, content, source_app, created_at, starred, pinned)`
    — `type` ∈ `text|image|file`. Для `image` — путь к превью-PNG в
    `%APPDATA%/Copycat/previews/`. Для `file` — JSON-список путей
    (храним ссылки/пути, не копируем сами файлы).
  - `tags(id, name)`, `item_tags(item_id, tag_id)` — many-to-many.
- **Retention**: лимит по количеству записей (настраиваемый, по
  умолчанию 1000). При превышении — удаление старейших non-starred
  записей. Starred записи не удаляются автоматически.
- **Tray + hotkey**: иконка в трее (Open / Pause capture / Quit),
  глобальный хоткей (по умолчанию `Ctrl+Shift+V`, настраиваемый)
  открывает/скрывает overlay-окно. Автозапуск с Windows — опционально,
  через `app.setLoginItemSettings`.
- **IPC API**: `get-items(query, typeFilter, tagFilter)`,
  `copy-item(id)`, `paste-item(id)` (копирует в буфер, опционально
  эмулирует Ctrl+V в активное окно), `toggle-star(id)`,
  `add-tag/remove-tag(id, tag)`, `delete-item(id)`, события
  `item-added` (push при новом элементе).

### Renderer (React)

- `SearchBar` — debounce 150мс, поиск по content/tags через SQL (не
  фронтовый фильтр — для масштаба на тысячах записей).
- `TabBar` — History / Starred.
- `TagFilterRow` — чипы тегов со счётчиком, multi-select, OR-логика по
  умолчанию (как на макете).
- `ItemCard` — иконка типа, превью (текст — первые строки, изображение
  — thumbnail, файл — иконка+имя), теги-чипы, кнопки copy/star/delete,
  app-источник.
- `ItemGrid` — горизонтальная лента, виртуализация `react-window`.
- `TagEditor` — попап добавления/снятия тегов на карточке.
- Хоткеи внутри окна: `Enter` — paste, `Space` — preview, `Esc` —
  скрыть окно / сбросить поиск.

### Data flow

Clipboard event → watcher определяет тип → дедуп по хэшу → `INSERT` в
SQLite → IPC `item-added` → store в renderer обновляется →
ре-рендер `ItemGrid`. Поиск/фильтр тегов — отдельный IPC-запрос
`get-items` с SQL `WHERE`, не клиентская фильтрация.

### Error handling

- Неподдерживаемый/пустой формат буфера — пропускается, без падения.
- Путь файла из истории не существует на момент paste — тост «файл не
  найден», запись остаётся в истории, визуально помечается как
  недоступная (приглушённая иконка).
- Ошибки SQLite — логируются в `%APPDATA%/Copycat/logs`, перехватываются
  в storage layer, не приводят к падению приложения.

## Вне рамок (YAGNI)

- Синхронизация между устройствами / облако.
- Редактирование содержимого элементов (только копирование/вставка).
- Шифрование истории (можно добавить позже как отдельная задача).
- Распознавание и блокировка чувствительных данных (пароли и т.п.) —
  не в этой итерации.

## Тестирование

- Unit: storage layer (Jest + временная SQLite БД), определение типа
  clipboard-содержимого, дедупликация.
- Integration: IPC-хендлеры (main ↔ renderer контракт).
- E2E: Playwright — основные флоу (copy → появляется в ленте, поиск,
  фильтр по тегу, paste, star/unstar, delete).
